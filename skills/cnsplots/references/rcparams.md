# cnsplots rcParams contract

The style is plain `matplotlib.rcParams`. There is no custom renderer, so any
matplotlib artist you add inherits it automatically **as long as you do not
hardcode a competing value**. Read this before customizing anything.

Regenerate the tables for the installed version:

```bash
python3 $SKILL_DIR/scripts/dump_style.py rcparams
python3 $SKILL_DIR/scripts/dump_style.py --markdown rcparams   # to refresh this file
```

Values below were measured against **cnsplots 0.8.0** as a real before/after
diff of `rcParamsDefault`. Treat them as the current contract, not as
guaranteed constants.

## Which call applies the style

`cns.figure()` applies the full style itself; it does **not** merely size a
canvas. Measured from clean `rcParamsDefault`, calling only
`cns.figure(width=200, height=160)` already yields
`axes.linewidth = 0.5`, `axes.spines.top = False`, `savefig.dpi = 288`. After
`setup_matplotlib()`, a following `cns.figure()` changes **zero** further
rcParams.

So:

- `cns.figure(...)` — single figure: styles *and* creates it. Do not also call
  `setup_matplotlib()`.
- `cns.setup_matplotlib(...)` — style only, no figure. Use when you create the
  figure yourself (`plt.subplots`, `plt.figure`) or style a whole script.
- `cns.setup_ax(ax)` — retrofit one existing axes, e.g. from seaborn, scanpy, or
  gseapy, created before the style was active.

## Sizing: the unit is points

From 0.8.0, `width` / `height` on `cns.figure()` and `mp.panel()` — and
`max_width` on `cns.multipanel()` — are **points**, 1/72 inch. Internally
`inches = points / 72`. The figure then renders at `settings.figure_dpi` (144),
so the display canvas is 2x the number you passed; export uses
`settings.savefig_dpi` (288), 4x. Measured: `cns.figure(width=200, height=160)`
gives `get_size_inches() == (2.778, 2.222)`, a **400x320** display canvas at
144 dpi, and an 800x640 PNG with `bbox_inches=None` at 288 dpi.

Names for this changed in 0.8.0. 0.7.0 called the same numbers "pixels at 72
per inch"; the numeric defaults and the arithmetic are unchanged, only the noun
and the adding of `unit=`.

Pass `unit=` to scale an explicitly supplied size:

```python
cns.figure(2, 1, unit="in")        # 2x1 inch
cns.figure(50.8, 25.4, unit="mm")  # 183 mm double column
cns.figure(519, 288)               # points, the default unit
mp = cns.multipanel(max_width=519, unit="pt")
```

Only explicit values of `width`, `height`, and `max_width` are scaled.
**An omitted dimension comes from `cns.settings` in points no matter what `unit`
says** — `cns.figure(height=100, unit="mm")` takes 100 mm for height but the full
150-point `figure_width`, not 150 mm; verified `(2.083, 3.937)` inches.
`mp.panel()` inherits the unit from its `multipanel`. Panel *margins* and
*margin defaults* are always points, and `pad_left` / `pad_top` are always
display pixels, for every unit — verified: `margin_right=2` stores `2` under
`pt`, `in`, and `mm` alike.

Note `figure.dpi` itself is **not** in the rcParams diff below; cnsplots sets
the figure's dpi on the figure object, and `mpl.rcParams["figure.dpi"]` stays at
100. Never derive panel geometry from `rcParams["figure.dpi"]`.

## Rules for custom artists

**Inherit, do not restate.** The style only reaches your artist if you leave the
property unset. Each line below overrides a key the table above deliberately
set, and silently defeats it:

```python
ax.set_xlabel("Time", fontsize=11)            # defeats axes.labelsize = 8
ax.legend(frameon=True, fontsize=9)           # re-adds the frame, defeats 7pt
ax.tick_params(width=1.0, length=4)           # defeats 0.6 / 2.0
ax.spines["left"].set_linewidth(1.0)          # defeats axes.linewidth = 0.5
ax.set_title("Result", fontweight="normal")   # defeats axes.titleweight = bold
```

Write instead:

```python
ax.set_xlabel("Time")                          # 8pt, from axes.labelsize
ax.legend()                                    # frameless, 7pt
ax.set_title("Result")                         # 8pt bold
```

Note the inverse trap: keys cnsplots does **not** touch stay at the matplotlib
default, so passing them explicitly changes nothing. `lines.linewidth` is 1.5 in
both, so `ax.plot(x, y, linewidth=1.5)` is a no-op, not a violation. Only the
keys in the table above are part of the contract.

**When you must pick a value, read it from the live config** rather than typing a
literal, so it tracks the installed version:

```python
import matplotlib as mpl
import cnsplots as cns

lw = mpl.rcParams["axes.linewidth"]            # 0.5
small = cns.settings.legend_fontsize           # 7
ax.axhline(0, linewidth=lw, color="black")
ax.annotate("n = 42", (0.02, 0.95), xycoords="axes fraction", fontsize=small)
```

**Colors:** use the palette, not ad-hoc hex. `cns.RED` etc. are the named hex
constants; `cns.palettes(name)` returns a list of **RGB float tuples** for
qualitative names (and a colormap for the few continuous ones — see below), not
hex strings; `axes.prop_cycle` supplies colors automatically when you omit
`color=`.

```python
colors = cns.palettes("Ecotyper1")             # [(0.839, 0.216, 0.180), ...]
ax.plot(x, y1)                                 # cycles automatically
ax.plot(x, y2, color=cns.BLUE)                 # explicit, still on-palette
```

`cns.palettes()` resolves names from the cnsplots palette registry, not from
matplotlib's colormap list, and the return type follows the palette kind.
Measured on 0.8.0: of the 33 registered names, 28 are qualitative and return a
list of RGB float tuples; the 5 continuous ones — `parula`, `BuRd_custom`,
`WhYlOrRd_custom`, `OrBu_custom`, `YlGnBu_custom` — return a
`LinearSegmentedColormap`, so `len(cns.palettes("parula"))` raises `TypeError`.
A plain matplotlib colormap name that is **not** registered raises
`RuntimeError: Wrong Choice!` — verified for `'gnuplot'`, `'viridis'`,
`'magma'`, `'hot'`, and `'bwr'`. Since `settings.palette_seq` defaults to
`'gnuplot'`, passing that setting straight to `cns.palettes()` always fails; for
sequential mapping use `color_map=` on `cns.figure()` / `mp.panel()` or
`plt.get_cmap(...)`. List the registry with
`python3 $SKILL_DIR/scripts/dump_style.py palettes` or `cns.available_palettes()`.

**Do not mutate `mpl.rcParams` directly.** Use `cns.settings.context(...)` so the
change is scoped and reversible; direct assignment leaks into every later figure
in the same process. Verified: `palette_qual` returns to `Ecotyper1` on exit.

```python
with cns.settings.context(palette_qual="Set2", axes_linewidth=1.0):
    cns.figure(width=200, height=150)
    ...
    cns.savefig("out.svg")
```

From 0.8.0 the block wraps `matplotlib.rc_context()`, so **rcParams are restored
too**, not just the `cns.settings` fields. Verified: with
`context(axes_linewidth=1.5)` + a `setup_matplotlib()` inside the block,
`mpl.rcParams["axes.linewidth"]` is `1.5` inside and back to `0.5` on exit;
nested contexts unwind in order (`1.5` -> `3.0` -> `1.5` -> `0.5`); and an
exception raised inside the block still restores (`0.5` after the traceback).
Backend changes and font/colormap registrations are **not** undone: a
`font_manager.addfont()` inside the block stays registered after it exits.

## Export keys worth knowing

`svg.fonttype = 'none'` keeps SVG text as editable text instead of outlines,
which is the point of the Illustrator workflow. `pdf.fonttype = 42` embeds
TrueType for the same reason. `savefig.transparent = True` means no white
background: check your figure against a dark viewer background before assuming
it is blank. `savefig.bbox = 'tight'` with `pad_inches = 0.01` means the saved
file is cropped to content, so the on-disk aspect ratio can differ slightly
from the requested point size — and on a sparse canvas it can differ a lot; see
`bbox_inches=None` in [troubleshooting.md](troubleshooting.md).
